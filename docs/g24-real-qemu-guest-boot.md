# G2.4 — Real QEMU TCG synthetic Guest boot, NOT Firecracker

**Functional boot experiment. Not KVM, Jailer, guest identity attestation, or a general-purpose code sandbox.**

GitHub-hosted, no-secret CI downloads ONLY the G2.3 hash-pinned Firecracker CI x86_64 Linux 6.18.51 ELF and config, requires CONFIG_PVH=y, builds the G2.1 static PID1 ext4 rootfs, and boots it in QEMU with the microvm machine using TCG-only software virtualization. No /dev/kvm access, no NIC, no model credentials or external project code.

The Guest must emit an exact fresh nonce-correlated serial readiness line. Parent process kills and reaps QEMU process group after a bounded run; raw serial console bytes remain in a deleted temporary directory. Only an unsigned JSON artifact survives with asset hashes, boolean readiness, cleanup outcome, and explicit no-Firecracker/no-KVM/no-security claims.

QEMU microvm is inspired by Firecracker hardware architecture but it is NOT Firecracker. This test can reveal boot incompatibilities in the kernel/virtio/ext4/PID1 and cannot close G1.9/G2.0 Firecracker actual guest boot or tenant sandbox safety. Ubuntu apt QEMU is not yet reproducibly pinned; S3 kernel hash was generated by PR-controlled CI, not a release signature.
